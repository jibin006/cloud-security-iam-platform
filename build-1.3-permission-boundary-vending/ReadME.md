I built a permission boundary vending machine on AWS Lambda. The problem it solves is developer IAM escalation — if you give teams iam:CreateRole directly, they can attach AdministratorAccess and own the account in three API calls. The vending machine is the only path to create roles. It enforces a permission boundary at creation time — no window where the role exists without a ceiling. I validated three attack paths: direct IAM bypass, confused deputy via external trust principal, and boundary self-removal from an assumed role session. I also tightened the Lambda's own execution role from IAMFullAccess down to three scoped actions with a boundary condition on CreateRole — because the Lambda itself was an escalation vector if compromised. The SCP that would enforce this at org level exists but isn't attached due to org permission constraints — I documented that as residual risk with the compensating control.
